The Problem

Why Do 60%+ of First-Time Open-Source Contributors Drop Out?

Contributing to unfamiliar codebases is riddled with unwritten rules, fragmented documentation, and high friction.

🚧 Friction #1

The "Hidden Rules" Maze

Should PRs target main or dev? What branch naming pattern is mandated? How do you run the test suite?

Result: PRs rejected by maintainers over branch or format violations.
⚖️ Friction #2

The AI Policy Minefield

Some projects ban LLM code entirely; others require explicit PR disclaimers or permit it only for test generation. Unsuspecting devs get flagged or banned.

Result: Contributor hesitation and wasted development effort.
📦 Friction #3

Issue Overwhelm & Stagnation

Repositories have hundreds of issues. "Good first issue" tags are often outdated, claimed, or deceptively complex architectural refactors.

Result: Paralysis of choice; newcomers don't know where to start.
💡
The Solution: Intelligent Signal Synthesis
OSS Contributor Assistant parses repo signals automatically and hands contributors a tailored, 6-step flight plan.

Architecture

Lightweight, Decoupled 3-Tier Architecture

Designed according to SOLID principles with fast local caching and zero cloud dependencies.

1

Reactive Client Layer

  • • Single-page app in frontend/index.html
  • • Dynamic dark mode & smooth micro-animations
  • • Inference Model Dropdown with live badge sync
  • • 1-click terminal command copy buttons
2

FastAPI Orchestration Core

  • • Asynchronous REST endpoints (/analyze)
  • • 3-Tier GitHub Credential discovery (5,000 req/hr)
  • • Convention Engine (target branch, regex rules)
  • • Local JSON persistence in data/*.json
3

Local Ollama Inference

  • • Private LLM running on localhost:11434
  • • Default: gemma4:12b
  • • Alternative: llama3.2:1b
  • • Context-aware roadmap synthesis & guidance
Pipeline Flow: GitHub API → Signal Extraction → Prompt Synthesizer → Ollama Inference → JSON Cache → Interactive SPA
